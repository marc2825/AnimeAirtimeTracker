## 2. プロダクト定義

**「日本のアニメ放送編成を、今週から過去まで横断的に調べられるサイト」**。仮称を「アニメ放送枠観測所」に改める（深夜帯以外の枠も扱うため。英名 Anime Airtime Tracker）。

| 区分 | 内容 |
| --- | --- |
| 既存サービスと重なる入口 | 週間番組表、今期一覧、局別表示、新/終/再の表示、作品ごとの放送一覧 |
| 独自価値 | **放送枠の年表**（クールごとの作品変遷・時刻移動・局）、出典と判定根拠つきの枠所属、編成統計（曜日×時刻、局別、同時放送数、関東↔関西の遅れ）、集計単位と対象範囲の常時明示 |
| v1 でやらないこと | アカウント、通知、視聴記録、配信サービス網羅、画像収集、ジャンル/スタッフ補完、公開編集 |

しょぼいカレンダーは番組表・作品ページ・録画予約を高精度に提供しているため、番組表単体では競合しない。本サイトは同データを**編成の時系列として再構成**することに価値を置き、各作品から出典ページへリンクする。

## 3. アーキテクチャ

```
しょぼいカレンダー db.php (XML)
   │  直列キュー・応答後≥2s+ジッタ・429/Retry-After・指数バックオフ・独自UA
   ▼
src/ingest/  plan → fetch → parse/validate → normalize → upsert (Tx) → derive
   │  raw XML(gzip)+hash, FetchLog, ImportRun, BroadcastRevision
   ▼
PostgreSQL (Prisma 7 + adapter-pg)
   ▲  src/server/queries/* ("use cache" + cacheLife + cacheTag)
   │
Next.js 16 App Router（Server Components 中心、Client は操作部品のみ）
```

- **ドメイン層** `src/domain/`: アニメ時刻（05:00 切替、25:30 表記）、クール、フラグ、統計、枠推定。DB 非依存・純関数・テスト必須。
- **取り込み層** `src/ingest/`: Syoboi クライアント、XML パーサ、計画、DB 取り込み、派生計算（枠所属）。CLI は `scripts/ingest.ts`。
- **サーバ層** `src/server/`: Prisma クライアントとクエリ。UI はここ以外から DB に触れない。
- **UI 層** `app/` + `src/components/`: デザイントークン（CSS 変数）+ CSS Modules。外部 UI ライブラリは入れない（ネイティブ `<dialog>`/`<details>`/popover で足りる）。グラフは SSR 可能な SVG/CSS Grid を自前実装。
- **キャッシュ**: `cacheComponents` 有効。DB 読み取りは Suspense 内のリクエスト時処理とし、ビルドは DB 不要。データ関数は `"use cache"` + `cacheLife`（15分）+ `cacheTag("dataset")`。
- **手動補正**: `data/overrides/*.json`（理由・根拠つき、PR でレビュー）を取り込み時に適用。DB 上の値を上書きしても次回取り込みで失われない。
- **管理**: Web 管理画面は v1 で提供しない（`/admin` は 404）。運用は CLI。公開の `/status` は実際の ImportRun のみ表示。

## 4. データモデル（要点）

`Channel`（媒体 TERRESTRIAL/BS/CS… と 地域 KANTO/KANSAI… を別カラム）、`Title`（しょぼい TID 単位＝シーズン単位の作品。シリーズは読み一致による派生グループ）、`Broadcast`（PID 単位の放送イベント。JST 実時刻＋アニメ日付/曜日/分、`flags`、`deleted`、`rerunBasis`）、`BroadcastRevision`（変更履歴）、`Slot`/`SlotMembership`（種別 OFFICIAL/SOURCE_LABEL/INFERRED、判定方法・根拠・信頼度）、`ImportRun`/`FetchLog`/`RawPayload`（取得履歴と生データ）。外部 ID は `(source, externalId)` で一意。未知は `null`（false と区別）。

## 5. 主要画面

| パス | 目的 | 主要要素 |
| --- | --- | --- |
| `/` | 入口 | 今日の放送（アニメ日付）、曜日/局クイックフィルタ、注目の枠、統計プレビュー、更新日時 |
| `/schedule` | 最頻用 | 週ナビ、グリッド（時間軸 05:00–29:00、24時線、現在線、重複の横並び）/リスト切替、局・地域・再放送フィルタ、URL 共有。モバイルは日別リスト |
| `/search` | 探索 | キーワード＋折りたたみ詳細条件、条件チップ、件数、並び替え、ページング、作品/放送/枠切替 |
| `/titles/[tid]` | 作品 | ヘッダー、局別放送一覧（初回・時刻・話数・変更）、関連枠、読み一致の関連作品、出典リンク |
| `/slots/[slug]` | **核** | 概要、種別バッジ、**クール年表**、時刻変更履歴、作品一覧、年別集計、判定根拠 |
| `/stats` | 分析 | 曜日×時刻ヒートマップ、クール推移、局別、同時放送数、関東↔関西の遅れ。全図に単位・範囲・再放送扱いを表示、表切替 |
| `/about` | 信頼 | 出典・利用条件・方法論・定義・限界・訂正窓口 |
| `/status` | 透明性 | 最終取得、対象範囲、取得件数、失敗の有無 |

## 6. デザイン方針

コンセプト「**深夜の編成表**」: 夜のネイビーを基調に、放送信号を思わせるシアンと、新番組を示すコーラルをアクセントにする。七曜（月火水木金土日）を日本の曜日色で小さく示す（必ず文字と併記）。数字・時刻は等幅数字。24時の日付変更線と現在時刻線を番組表の象徴的要素にする。詳細は [design-system.md](design-system.md)。

## 7. 開発順序

1. 依存更新・ハーネス再編・CI（本ブランチ最初のコミット群）
2. ドメイン層（時刻・クール・フラグ）＋テスト
3. Prisma スキーマ再設計・マイグレーション・ローカル DB
4. Syoboi Provider・取り込み・fixture テスト → **今期・対象局の実データ取り込み**
5. デザインシステム・共通レイアウト
6. 番組表 → 作品 → 枠 → 統計 → 検索 → トップ → about/status
7. 過去クールのバックフィル（直近数年）と枠算出
8. E2E・スクリーンショット検証・アクセシビリティ・SEO・セキュリティヘッダ
9. 運用文書・README・残課題整理

各段階でコミットを分け、lint / typecheck / test / build を通す。
